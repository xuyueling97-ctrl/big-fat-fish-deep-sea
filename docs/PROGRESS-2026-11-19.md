## 18:40–18:48 追加修复：敌鱼速度被鱼群数量误放大

**这是大地图改造引入的语义错位，影响很大。**

`spawnEnemy()` 里一直有这么一行：

```js
speed: Utils.rand(52, 96) * (1 + diff * 0.045)
```

其中 `diff` 原本是**困难度索引**（14 → 24）。大地图改造把 `enemyTargetCount()`
改成返回**鱼的数量**（63 → 96）后，这行仍然从它取值，于是：

| | 改造前 | 改造后 |
| --- | --- | --- |
| `diff` 取值 | 14–24 | 63–96 |
| 速度系数 | 1.6–2.1 | 3.8–5.3 |
| 掠食者速度 | ~100–160 | ~200–500 |

玩家基础速度是 306/s，但掠食者追击时还能再叠 `+132 * chase` 的加速度，
实际跑得比玩家快。实测**一局只撑 39.6 秒、吃到 5 条鱼**就三条命全丢。

**修复**：抽出单一困难度来源 `difficultyIndex()`（`14 + min(10, elapsed/22)`），
鱼速读它，鱼数由它 ×4.5 得出。两者不再共用一个语义混乱的返回值。

**修复前后对比**（`tests/curve.js`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 单局时长 | 39.6 s | 123.5 s |
| 最终体型 | 16.3（鱼苗） | 34.2（中鱼） |
| 吃到鱼数 | 5 | 27 |
| 走到阶段 | 鱼苗 | 中鱼 |

同时修正了 `curve.js` 的自动游玩逻辑：它是在「地图=视口」时期写的，
距离用 `Math.hypot` 直算（环形世界下会把跨边界的近鱼当成很远），
目标点也被 `clamp` 到视口而不是世界。现改为 `ringDist` / `wrapDelta` 走最短路径，

## 21:40 追加修复：大后期被多条大鱼围攻致死（6000 分后）

**用户反馈**：6000 分以上的大后期，会一次性冒出多条比自己大的鱼，把玩家围死。

先做量化诊断（`tests/out/late-pressure.js` 的前身脚本），确认了三层叠加原因：

### 根因 1：掠食者速度上限没有和玩家挂钩（最致命）

```js
const maxSp = e.speed * 1.9 * diff;   // e.speed 最高 ~96*2.1，diff 最高 1.42
```

理论峰值 539 px/s，而玩家满级时只有 `306 * 0.78 = 239 px/s`。
实测满级场景里大鱼跑到玩家的 **2.1–2.2 倍速**——玩家在物理上跑不掉，
只能靠 1.65s 冷却的冲刺续命，被追上只是时间问题。

**修复**：`maxSp` 再取一次 `min(maxSp, p.baseSpeed * PREDATOR_SPEED_CAP)`，上限 1.06。

### 根因 2：致命鱼只进不出，占比单调上涨

玩家永远吃不到比自己大的鱼，而每吃掉一条小鱼，补充的新鱼里又有约 30% 是致命鱼。
实测 140 秒内致命鱼从 29 条涨到 49 条，占比 30.2% → 51%，一路不加不减地爬。

**修复**：`lethalCount()` / `lethalCap()`，致命鱼数量超过 `enemyTargetCount() * 0.3` 时，
新刷的鱼一律变成可吃的鱼。实测占比稳定在 30.2%，不再上涨。

### 根因 3：所有大鱼同时朝玩家聚集

即使总量受控，380px 内的大鱼全部扑过来仍会从四面八方合围，玩家往哪躲都撞上另一条。

**修复**：`pickActiveChasers()` 只选**最近的 2 条**致命鱼主动追击，其余保持漫游。

### 补充：受伤冲击波

三层修完后仍有 1.5s 无敌一结束就再被撞上的情况（`minHurtGap` 恰好等于无敌时长）。
`hurt()` 里加了冲击波：把周围 240px 内的大鱼按距离推开最多 170px。
注意这里**改坐标而不是改速度**——速度会被上面那条 `maxSp` 钳制掉，推不动。

## 2026-11-20 追加修复：冲刺穿边界后画面错位与鼠标失灵

**用户反馈**：「冲刺的时候有时候卡，之后错位」。

先量后改。结论：**不是性能问题**，是两处耦合的环形世界坐标 bug。

### 排除项（先量再动手）

| 怀疑点 | 实测 | 结论 |
| --- | --- | --- |
| 冲刺掉帧 | 冲刺帧均 7.22 ms vs 闲置 7.15 ms | 否 |
| update+draw 太重 | 90 条鱼时 0.25 ms 中位 | 否 |
| 音效卡顿 | `Sfx.dash()` 中位 0.3 ms / 最大 3.3 ms | 否 |
| 冲刺穿模（tunneling） | 单步 12.5 px vs 碰撞半径 77.5 px | 否 |

为什么偏偏是冲刺：冲刺速度是常速的 2.43×（239 → 580 px/s），
30 秒内穿边界次数从 2 次涨到 3 次；而玩家又习惯用冲刺往边缘逃，于是撞上下面两个 bug。

### 根因 1：折返周期不一致

`wrap()` / `wrapPos()` 用 `worldW + 2m`（`m = e.r + 6`）为周期，
而 `wrapDelta()` / `toScreenX()` / `toScreenY()` 用 `worldW`。

每穿一次接缝，屏幕坐标就凭空跳 `2m` px：实测 r=13 时 **-41.2 px**，r=62 时 **-126.9 px**。
更糟的是不同体型的鱼阈值与时刻都不同，整群鱼会在接缝处「剪切」错位。

### 根因 2：相机停在了另一个世界带

`updateCamera()` 用 `wrapDelta` 收敛，只会到达「相差整张地图」的等价解，
之后 `cam.x` 一直停在距 `player.x` 约 **-0.85 个世界** 的位置且从不归一化。
`setPointer()` 又直接算 `x / this.S + this.cam.x`，于是鼠标反算差一整圈：

鼠标精确压在鱼身上，鱼仍以 **238.7 px/s** 自漂，600 帧后不变，只有重开一局才好。

### 修复（`js/game.js`，4 个方法，未动任何平衡常量）

- `wrap(e)` / `wrapPos(e)`：改为 `e.x -= Math.floor(e.x / this.worldW) * this.worldW;`（y 同理）
- `updateCamera(dt)`：阻尼跟随之后，把 `cam` 归一化到玩家所在世界带
  （`this.cam.x = p.x + this.wrapDelta(this.cam.x - p.x, this.worldW)`）
- `setPointer(x, y)`：反算出世界坐标后，按 `wrapDelta` 相对玩家折算再存储

`+2m` 余量本来就多余——渲染已经用 `wrapDelta` 取最近的那份拷贝，它只是那 2m 跳变的直接来源。

## 2026-11-20 追加修复：点摇杆/冲刺按钮黑屏一闪

**用户反馈**：「点遥感和冲刺会黑屏一瞬间」。

### 根因：canvas.width 赋值会清空位图，且发生在 draw() 之后

`resize()` 无条件执行 `this.canvas.width = ...`。按规范，给 canvas 的
`width`/`height` **赋值（哪怕赋的是当前同一个值）会重置整个位图**，内容全部清空。
实测：填满红色后赋同值，像素 `255 → 0`。

触发链：

1. 摇杆和冲刺按钮的 `pointerdown` 都做了 `stopPropagation()`，但 **`touchstart` 是独立事件**，
   不受 `stopPropagation` 影响，照样冒泡到 `window` 上的 `noteTouchInput()`
2. `noteTouchInput()` → `enableTouchUI()` → `syncOrientation()` → `requestAnimationFrame(() => game.resize())`
3. 主循环的 `frame()` 在**上一帧末尾**就重新注册了自己，所以它在 rAF 批次里总排第一；
   `resize` 注册得更晚 → **同一帧内先 `draw()` 后 `resize()`**
4. `resize()` 清空位图后当帧不再重绘 → 浏览器合成出一帧全黑

### 为什么是「一瞬间」

只有一帧，约 16 ms。在深色游戏画面上肉眼看到的就是一次黑闪。

### 修复（`js/game.js` 的 `resize()`）

先算目标位图尺寸，**尺寸没变就绝不碰 `canvas.width/height`**：

```js
const nextW = Math.round(w * dpr);
const nextH = Math.round(h * dpr);
const bitmapChanged = this.canvas.width !== nextW || this.canvas.height !== nextH;
...
const S = Utils.clamp(Math.min(w, h) / 620, 0.5, 1.8);
if (!bitmapChanged && S === oldS) return;   // 布局与缩放都没变，直接早退
if (bitmapChanged) { this.canvas.width = nextW; this.canvas.height = nextH; }
```

早退是安全的：`w/h/dpr/S/vw/vh/worldW/worldH` 在尺寸不变时算出来也是同值，
没有需要额外同步的状态。

### 修复前后

| --- | --- | --- |
| 点摇杆后画布亮度最小值 | **0**（全黑 1 帧） | 46.4 |

## 环境备忘

- PowerShell 控制台按 GBK 解码中文，`node` 直接打印中文 JSON 会乱码 → 报告一律重定向到文件再用 `read_file` 读
- `git push` 的进度走 stderr，PowerShell 会报 `NativeCommandError` 且 `$LASTEXITCODE` 可能为 1，**这是假警报**；以输出里的 `<sha>..<sha>  main -> main` 为准
- PowerShell 不支持 heredoc（`<<'MSG'`），多行提交信息要写成临时文件再 `git commit -F`
- 项目根目录改名会因 `codely.exe` 占用 cwd 而失败
- Edge 路径写死：`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`
